## Pitfall: cycle 890 .format() NID-N mismatch (NEW — codification)

**Trigger**: The cp source's LINEB_PROSE .format() call hardcodes NID0..NID{k-1} kwargs for the cp source's DELTA=k. If the new cycle's DELTA < k, the .format() call crashes with `IndexError: list index out of range` when it tries `NEW_IDS[k-1]`.

**Pre-flight (cycle 890)**: The cp source `_cycle889.py` has DELTA=4, so .format() hardcodes NID0..NID3. Cycle 890's DELTA=2 means NEW_IDS only has 2 elements — `NEW_IDS[2]` and `NEW_IDS[3]` raise IndexError. The LINEB_PROSE template itself only references {NID0} and {NID1} (the template was already updated to match delta=2 in the body of the f-string), but the .format() kwargs at line 512 still passed all 4 NID values, causing the crash.

**Recovery**: drop NID2 and NID3 from the .format() kwargs to match the new cycle's DELTA. The LINEB_PROSE template's body is already DELTA-aware (it uses `{NID0}` and `{NID1}` only for DELTA=2), so the .format() kwargs simply need to match — pass only the NID-N values that the template actually references.

**Why this matters**: A cycle that crashes at the .format() call has already done partial Phase 2/3 work (atomic write to index.html with new marker, atomic write to deploy-stamp.txt). The recovery path is to `git checkout -- index.html deploy-stamp.txt` to revert the partial writes, then re-run. The tweet.json changes (the byline fixup + new record commits) are still in place from the .fix_byline and the fetcher, so re-running proceeds cleanly.

**Codification**: this is the **NID-N .format() mismatch pitfall** (NEW, codified cycle 890). The fix is to always verify that `.format()` kwargs include exactly NID0..NID{DELTA-1} where DELTA is the new cycle's delta, NOT the cp source's delta. Future cycles should grep for `NID0, NID1, NID2, NID3` in the LINEB_PROSE .format() call and drop any NID-N that exceeds the new cycle's actual NEW_IDS list length.
